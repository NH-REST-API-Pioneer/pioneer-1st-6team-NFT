# R05 · 실시간 8개 API 의 요청 명세가 서로 다릅니다 (필수 여부·샘플·경로·요청 제한)

- 섹터: 0 → 6 · 종류: 명세 오류 · 검증: 문서 대조 + 실제 호출(11/22, 필수 표기 부분) · AI 영향: 중
- 상태: 올릴 준비 됨. 4번(요청 제한)은 문서 차이만 — 구독 메시지 속도·20건 상한 호출은 아직 못 함

```text
[제보] 실시간 8개 API 의 요청 명세가 서로 다릅니다: 필수 여부(KA 만 Y), FB 샘플 누락, 요청 샘플 경로, 요청 제한

팀: team-06
환경: 개발자센터 웹 가이드·「Excel 다운로드」(2026-11-20 확인)
대상: 국내_시세체결 KA, 국내_시세호가 KB, 국내_시세체결(야간) KC, 국내_시세호가(야간) KD, 국내_주문/체결 O1_K, 해외_시세체결 FA, 해외_시세호가 FB, 해외_주문/체결 O1
      예) https://apidev.futures.co.kr/#/api?g=123&a=191&v=1 (KA), https://apidev.futures.co.kr/#/api?g=126&a=189&v=1 (FB)

기대 결과: 같은 구독 메시지 형식이므로 8개 명세가 같아야 함

실제 결과:
  1. 필수 여부
     | 필드             | KA | KB·KC·KD·FA·FB | O1_K·O1 |
     | header.action    | Y  | N              | N       |
     | body.action_code | Y  | N              | N       |
     | body.action_sym  | Y  | N              | (없음)  |
     action(A/D)·action_code 없이는 구독이 불가능하므로 N 은 틀린 것으로 보임 (header.api_ver 만 8개 모두 Y)
  2. FB(해외_시세호가)만 action_code·action_sym 샘플이 비어 있음 (다른 7개는 KA, A0169000, 6AU26 등)
  3. 「요청 샘플」 첫 줄이 GET /trade/v1/KA HTTP/1.1 (8개 모두 /trade/v1/{코드}). 실제 접속 경로는 같은 페이지 상단의 /trade/ws-stream?access_key=… 하나
  4. 요청 제한이 웹은 「API 디폴트」, 엑셀은 「전체 실시간 구독 제한은 20개입니다.」 — 구독 메시지에 초당 제한이 있는지 명세에 없음

호출 확인 (모의, 2026-11-22 23:17):
  - body.action_code 를 빼면 → {"type":"VALIDATION_ERROR","message":"action_code는 필수입니다."} 후 서버가 연결을 끊음  ← 명세 KB 등은 필수 N
  - body.action_sym 을 빼면 → RT_FAIL 「해당 종목에 대한 종목정보를 찾을 수 없습니다」 (서버가 빈 자리를 사용자 ID 로 채움, R19)  ← 명세 필수 N
  - FB 는 명세 샘플이 비어 있어도 action_code "FB" + 종목(6AZ26)으로 RT_INIT
  → 실제로는 action·action_code 가 반드시 필요하고 (빠지면 연결이 끊길 정도), 체결·호가는 action_sym 도 필요함

로그·캡처: 8개 요청 바디 표 캡처, (저장소) error_reports/6-실시간/logs/realtime_20261122_231702.json, 대조 결과 error_reports/0-명세대조/spec/compare_1120.tsv
영향: 명세의 필수 표기를 따르는 클라이언트·AI 에이전트가 KB 등에서 action·action_code 를 빼고 보낼 수 있음 (이때 서버가 응답 없이 무시하거나 연결을 끊음 → R04)
개선 제안: 8개 요청 명세의 필수 여부·샘플을 KA 와 같게 맞추고, 요청 샘플 경로를 /trade/ws-stream 으로, 요청 제한을 「구독 20건 (메시지 속도 제한 여부)」로 통일
```

## 남은 확인 (연결을 새로 열어야 함, 확인받고)

- 한 연결에서 구독·해제를 1초에 6번 → 속도 제한 오류가 나는지
- 서로 다른 종목 21개 구독 → 21번째에 EST06 이 오는지
