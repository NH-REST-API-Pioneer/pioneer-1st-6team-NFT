# R04 · 실시간 구독 메시지 형식이 틀리면 서버 처리가 제각각입니다 (무응답 / 말없이 연결 종료 / 오류 후 종료)

- 섹터: 6 (실시간), 10/27 검증·11/22 사례 추가 · 종류: 서버 동작 + 명세 누락 · 검증: 실제 호출 · AI 영향: 상 (잘못된 메시지 하나로 연결 전체가 끊김)
- 상태: 올릴 준비 됨 (10/27 초안 「제보 3」을 새 양식으로)

```text
[제보] 실시간 구독 메시지 형식이 틀리면 처리가 제각각입니다 (무응답 / 말없이 연결 종료 / 오류 후 연결 종료). 명세에는 실패 시 RT_FAIL 만 안내

팀: team-06
환경: 모의 (wss://apidemo.futures.co.kr), 2026-10-27 16:41 최초, 17:06~17:07 케이스별 재현, 2026-11-22 23:17 action_code 누락 추가 확인
대상: 실시간 구독 (KA·KB 로 확인)  https://apidev.futures.co.kr/#/api?g=123&a=191&v=1 (KA), https://apidev.futures.co.kr/#/api?g=123&a=192&v=1 (KB)
      실시간 처리 안내 「실패 시: RT_FAIL」

재현 절차:
  1. 접근토큰 발급 → 웹소켓 키 발급 → wss 접속 → session_init (INIT_SUCCESS 확인)
  2. 아래 메시지를 하나 보내고 5초 대기 → 이어서 정상 구독을 보내 연결이 살아 있는지 확인
  3. 케이스마다 새 연결로 반복

기대 결과:
  잘못된 요청에는 RT_FAIL(또는 오류 메시지)이 오고, 처리 방식이 일관됨

실제 결과:
  [내용 오류 → RT_FAIL, 연결 유지 (명세대로)]
  - 없는 종목 A999X999       → {"code":"RT_FAIL",…,"msg":"해당 종목에 대한 종목정보를 찾을 수 없습니다. [종목: A999X999]"}
  - 없는 실시간 코드 ZZ       → {"code":"RT_FAIL",…,"msg":"예외 발생 허용된 action_code가 아닙니다."}
  - action "X"               → {"code":"RT_FAIL",…,"msg":"예외 발생 잘못된 action 입니다. A: 구독, D: 해지만 사용 가능합니다."}
  [형식 오류 → 제각각]
  - body 없음 {"header":{"api_ver":"1","action":"A"}}
      → {"message":"body가 누락되었습니다.","type":"VALIDATION_ERROR"} 후 서버가 연결 종료
  - body.action_code 없음 {"header":{"api_ver":"1","action":"A"},"body":{"action_sym":"A756C000"}}  (11/22 23:17 추가 확인)
      → {"type":"VALIDATION_ERROR","message":"action_code는 필수입니다."} 후 서버가 연결 종료 (명세 필수 칸은 KA 만 Y, KB 등 나머지 7개는 N)
  - header 없음, {"header":null,"body":null}
      → 아무 메시지 없이 서버가 연결 종료
  - 필드를 최상위에 둔 형식 {"api_ver":"1","action":"A","action_code":"KA","action_sym":"A756B000"}
  - 「Excel 다운로드」 KA 시트 Request JSON 그대로 {"api_ver":"1","action_code":"KA","action_sym":"A756B000","header":null,"action":null,"body":null}
  - JSON 이 아닌 문자열
      → 세 경우 모두 응답 없음, 연결 유지 (이어서 보낸 정상 구독은 RT_INIT)

로그·캡처: (저장소) error_reports/6-실시간/logs/ws_subscribe_20261027_164158.json, logs/ws_fail_20261027_170754.json, logs/realtime_20261122_231702.json
          재현 스크립트 error_reports/6-실시간/check_ws_subscribe.py, check_ws_fail.py, check_realtime.py
영향:
  - 무응답: 구독이 안 됐는데 알 수 없음. 엑셀 실시간 시트 8개(11/20 판도 같음)의 Request JSON 이 바로 이 형식이라, 예시를 복사하면 조용히 구독이 안 됨
  - 연결 종료: 메시지 하나 실수로 같은 연결의 다른 구독이 모두 끊기고, 이유 메시지가 없는 경우도 있음 → 재접속이 늘어남
  - VALIDATION_ERROR 응답은 {"type","message"} 형식이라 구독 응답({"code","data","msg"})과 키가 달라 같은 코드로 처리할 수 없음
개선 제안:
  1) 형식 오류도 RT_FAIL(또는 VALIDATION_ERROR)로 일관되게 알리고 연결은 유지
  2) 형식 오류 때의 응답 형식·연결 종료 여부를 실시간 처리 안내에 명시
  3) 엑셀 실시간 시트 Request JSON 을 {"header":{"api_ver":"1","action":"A"},"body":{"action_code":"KA","action_sym":"A0169000"}} 로 수정
참고: team-08 「해외 실시간 구독 응답 필드」(11/05)는 응답 키(rt_cd/code)와 내용 오류의 RT_FAIL 을 다뤘고, 이 건은 형식 오류의 처리 방식이라 다릅니다.
```
