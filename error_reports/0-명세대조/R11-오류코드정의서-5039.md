# R11 · 오류 코드 정의서: 5039 가 서로 다른 뜻으로 두 번 있고, 첫 번째 뜻(「개장전」)은 실제와 다릅니다

- 섹터: 0 (문서) · 종류: 오류코드 문서 오류 · 검증: 문서 대조 + 다른 팀 실측·운영진 답변 · AI 영향: 중 (코드→뜻 표를 그대로 쓰면 원인을 잘못 판단)
- 상태: 올릴 준비 됨

```text
[제보] 오류 코드 정의서 「주문오류 ERROR」 표에 5039 가 두 번, 서로 다른 메시지로 있습니다 (1번 「거래소 (야간)개장전입니다」는 실제 5039 와 다름)

팀: team-06
환경: 개발자센터 「오류 코드」 페이지 > 「오류 코드 정의서 다운로드」 (오류코드_정의서.xlsx, 2026-11-20 받음)
대상: 정의서 「주문오류 ERROR」 시트, 「오류코드 목록」 시트의 [예시]

실제 내용:
  주문오류 ERROR 시트
    No 1   5039 | 거래소 (야간)개장전입니다.
    No 38  5039 | 처리불가 [(시장가)호가유형별 호가입력제한오류]
  오류코드 목록 시트 [예시]
    「5039 처리불가 [해당주문은 가격 보류 기준(100) 초과되었습니다(800)]」, 「5039 처리불가 [주문증거금총액 부족]」,
    「5039 처리불가 [호가단위(0.05). 오류]」, 「5039과 같은 경우 주문오류 조회 시 상세 내역 확인 가능」

기대 결과:
  코드 하나에 뜻 하나. 5039 가 여러 사유를 담는 「처리불가」 코드라면 표에도 그렇게 한 줄로

문제:
  - 같은 표에 5039 가 두 번 있고 뜻이 다름
  - 예시와 실제 응답(team-08 10/30 제보: 시장가 FAK → 5039 「처리불가 [시장가는 FOK, FAK 주문불가입니다 ]」, 운영진 확인)을 보면
    5039 는 「처리불가 [사유]」 형태의 포괄 코드인데, 1번 줄은 「거래소 (야간)개장전입니다」라는 한 가지 뜻으로 적혀 있음
  - 예시의 「주문증거금총액 부족」·「호가단위 오류」는 같은 표에 따로 52·50802 코드로도 있어, 어느 코드로 오는지 알 수 없음

영향:
  - 정의서를 코드→뜻 표로 쓰는 프로그램·AI 에이전트가 5039 를 「개장 전」으로 해석해, 실제 원인(체결 조건, 증거금, 호가 단위 등)과 다른 대응을 함
개선 제안:
  1) 5039 를 한 줄로 합치고 「처리불가 — 상세 사유는 메시지 [ ] 안과 주문오류내역 조회로 확인」으로 설명
  2) 「거래소 (야간)개장전」에 해당하는 실제 코드가 따로 있다면 그 코드로 고치기
  3) 52·50802 처럼 별도 코드가 있는 사유가 5039 로 올 때와 단독 코드로 올 때의 차이를 적기
```
