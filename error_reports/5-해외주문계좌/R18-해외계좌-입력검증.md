# R18 · 해외 계좌 조회 입력 검증: 없는 환산통화(XXX)가 오류 없이 「0」 손익 합계를 만들고, 쓰인 오류 코드 5009·7332 는 정의서에 없습니다

- 섹터: 5 · 종류: 입력 검증 누락 + 명세와 다른 동작 + 오류코드 문서 누락 · 검증: 실제 호출 · AI 영향: 상 (없는 통화로 조회하면 손익이 0 으로 보임)
- 상태: 올릴 준비 됨

```text
[제보] 해외_누적손익현황은 명세상 환산통화가 USD·KRW 2가지뿐인데, 없는 통화(XXX)도 오류 없이 받아 「USD의 XXX환산합계」를 모두 0 으로 돌려줍니다 (해외 계좌 조회 입력 검증이 제각각)

팀: team-06
환경: 모의 (apidemo.futures.co.kr), 2026-11-22 23:11 최초, 23:11·23:12 재현 (해외 모의 키)
대상: 해외_누적손익현황 POST /trade/v1/overseas/cumulative-pl, 해외_예수금조회 POST /trade/v1/overseas/deposit,
      해외_주문내역 POST /trade/v1/overseas/order-history, 해외_주문가능수량 POST /trade/v1/overseas/orderable-quantity

재현 절차:
  1. 접근토큰 발급 (해외 모의 키)
  2. 해외_누적손익현황 {"inq_strt_dt":"20261101","inq_ed_dt":"20261120","cvs_cur_cd":"USD"} 와 cvs_cur_cd 만 EUR·XXX 로 바꾼 요청
  3. 아래 표의 나머지 요청

기대 결과:
  누적손익 cvs_cur_cd 설명 「USD, KRW (2가지만 사용 가능)」에 따라 그 밖의 값은 거절. 다른 필드도 설명 밖 값은 거절하고, 쓰는 오류 코드는 정의서에 있음

실제 결과:
  | 요청                                               | 결과                                                        |
  | 누적손익 cvs_cur_cd=USD                            | 200, 마지막 행 「USD의 USD환산합계」, 금액 있음                |
  | 누적손익 cvs_cur_cd=EUR                            | 200, 「USD의 EUR환산합계」 (명세에 없는 통화인데 동작)          |
  | 누적손익 cvs_cur_cd=XXX                            | **200, 「USD의 XXX환산합계」, 실현손익·수수료·순손익 모두 0**   |
  | 예수금 cur_cd=XXX                                   | 400 7332 「[XXX]통화의 환율정보가 없습니다.」  ← 같은 「없는 통화」를 여기선 거절 |
  | 예수금 cvs_div=9 (명세 1:개별, 2:환산)               | 400 5009 「[환산구분] 필수항목 입력하세요.」  ← 값을 넣었는데 「필수항목 입력」 |
  | 주문내역 inq_div=9, trd_div_cd=9                    | 200 정상 (국내_주문내역은 같은 값을 5011 로 거절)              |
  | 주문가능수량 glb_ord_tp_cd=4(STOP-L), stop_pric 없음 | 200 정상 (명세: 「STOP 주문의 유형일때 필수」)                 |
  → 없는 통화를 넣으면 누적손익은 0 을, 예수금은 오류를 돌려줘 같은 실수가 API 마다 다르게 처리됨
  → 7332·5009 는 오류 코드 페이지·정의서에 없음. 5009 메시지는 원인(값이 틀림)과 다름

로그·캡처: (저장소) error_reports/5-해외주문계좌/logs/overseas_account_repro_20261122_231157.json (금액 값은 남기지 않고 「모두 0」 여부만),
          logs/overseas_account_20261122_231106.json, 재현 스크립트 error_reports/5-해외주문계좌/check_overseas_account.py
영향:
  - 환산통화를 잘못 넣은 프로그램·AI 에이전트가 오류 대신 「손익 0」을 받아 계좌 손익을 잘못 보고함
  - 조건부 필수(STOP 가격)를 빠뜨려도 주문가능수량이 정상으로 와서 실제 주문 단계에서야 문제가 드러남
개선 제안:
  1) cvs_cur_cd 는 명세대로 USD·KRW 만 받거나, 지원하는 통화 목록을 명세에 적고 그 밖은 7332 처럼 거절
  2) 주문내역 inq_div·trd_div_cd, 주문가능수량 glb_ord_tp_cd 범위 밖 값과 STOP 가격 누락을 거절
  3) 5009·7332 를 정의서에 추가하고, 5009 메시지를 「[환산구분] 값이 올바르지 않습니다」처럼 원인에 맞게
```
