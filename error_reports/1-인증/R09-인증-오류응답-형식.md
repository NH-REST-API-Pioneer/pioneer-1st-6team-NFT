# R09 · 토큰 발급 오류 응답의 `errorStatus` 타입이 혼재하고, 공식 가이드 예시(JSON 본문)대로 보내면 원인과 다른 메시지가 옵니다

- 섹터: 1 · 종류: 오류 응답 형식 불일치 + 문서 예시 오류 · 검증: 실제 호출 + 라이브 문서 대조 · AI 영향: 중 (정적 타입 파싱 깨짐, 공식 예시 따라 보내면 오진)
- 상태: 올릴 준비 됨

```text
[제보] 토큰 발급 오류 응답의 errorStatus 가 문자열/숫자로 섞여 오고, JSON 본문 전송 시 원인과 다른 「appkey 누락」이 옵니다 (소켓 안내 페이지 예시도 JSON 본문)

팀: team-06
환경: 모의 (apidemo.futures.co.kr), 2026-11-20 23:34·23:35 (토큰 발급 2회 동일), 23:39 (토큰 폐기 1회)
대상: 접근토큰 발급 POST /auth-service/v1/token, 접근토큰 폐기 POST /auth-service/v1/revoke
      오류 코드 페이지 https://apidev.futures.co.kr/#/api/info/error-code
      소켓 연결 및 세션 초기화 안내 https://apidev.futures.co.kr/#/api/info/socket-overview (01 접근 토큰 발급 예시)

재현 절차:
  1. 토큰 발급을 아래처럼 보내고 오류 응답을 비교
     (a) grant_type 없음 (form)  (b) appkey 없음 (form)  (c) grant_type 을 password 로  (d) appsecret 틀림
     (e) 같은 값을 form 이 아닌 JSON 본문(`Content-Type: application/json`)으로 전송
  2. 토큰 폐기를 appsecret 을 틀리게 해서 전송
  3. 개발자센터 「소켓 연결 및 세션 초기화 안내」 01번 예시와 「응답 테스트 개요 및 설명」 토큰 발급 예시 비교

기대 결과:
  1) 같은 API 의 오류 응답 스키마(errorStatus 타입 등)가 일관되고, errorPath 는 공개 경로를 반환
  2) 공식 가이드 예시끼리 본문 형식이 일치하며, form 이 아닌 Content-Type 에는 다른 API 처럼 ERC000 등 형식 오류를 반환

실제 결과:
  (a) EAU030 「필수 파라미터 누락: grant_type」  errorStatus: "BAD_REQUEST" (문자열)
  (b) EAU030 「필수 파라미터 누락: appkey」      errorStatus: "BAD_REQUEST" (문자열)
  (c) EAU023 「잘못된 파라미터: grant_type」     errorStatus: 400 (숫자)
  (d) EAU025 「잘못된 appkey 또는 appsecret」    errorStatus: 400 (숫자)
  → 같은 API 의 같은 HTTP 400 인데 errorStatus 타입이 다름 (이번에 확인한 다른 오류 EGW023·EG047·EGW000·EG049·EAU011·ERC002·ESTAT003·EST01 은 모두 숫자)
  (e) JSON 본문 → EAU030 「필수 파라미터 누락: appkey」 (errorStatus: "BAD_REQUEST")
      → appkey 를 보냈는데 「누락」으로 응답. 다른 API 는 Content-Type 이 틀리면 HTTP 415 ERC000 「지원하지 않는 Content-Type」(11/20 확인)
      → 특히 개발자센터 「소켓 연결 및 세션 초기화 안내」(`/#/api/info/socket-overview`) 01번 예시 자체가
        `Content-Type: application/x-www-form-urlencoded` 아래 본문을 JSON 객체 `{"grant_type": "client_credentials", "appkey": "...", "appsecret": "..."}` 로 잘못 기재해 놓아(「응답 테스트 개요」는 `grant_type=...&appkey=...`),
        공식 가이드를 보고 따라 하면 바로 이 오류에 걸림
  errorPath 가 공개 경로가 아니라 내부 경로로 옴: 토큰 발급 `/v1/oauth2/token`, 토큰 폐기 `/v1/oauth2/token/revokeP`

로그·캡처: (저장소) error_reports/1-인증/logs/auth_20261120_233527.json (T2~T6), logs/auth_20261120_233427.json (T2~T6), logs/revoke_20261120_233915.json (R6), 재현 스크립트 error_reports/1-인증/check_auth.py
영향:
  - errorStatus 를 정수(int)로 역직렬화하거나 비교하는 클라이언트(Java/Spring DTO 등)가 EAU030 에서 파싱 실패함
  - 「소켓 연결 및 세션 초기화 안내」 예시를 보고 JSON 본문으로 토큰 발급을 요청하면 「appkey 누락」이 와서 키 문제로 오해함
개선 제안:
  1) EAU030 의 errorStatus 를 숫자(400)로 통일하고, errorPath 는 공개 경로(`/auth-service/v1/token`, `/auth-service/v1/revoke`)로 반환
  2) 「소켓 연결 및 세션 초기화 안내」 01번 토큰 발급 예시 본문을 `grant_type=client_credentials&appkey=...&appsecret=...` (form-urlencoded)로 수정
  3) 토큰 발급에 form 이 아닌 Content-Type 이 오면 ERC000 또는 「application/x-www-form-urlencoded 로 보내야 합니다」 안내
```
