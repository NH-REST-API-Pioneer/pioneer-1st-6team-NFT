# R09 · 토큰 발급 오류 응답의 형식이 오류마다 다르고, 문서에 없는 코드·원인과 다른 메시지가 옵니다

- 섹터: 1 · 종류: 오류코드·메시지 (문서 누락·불일치) · 검증: 실제 호출 · AI 영향: 중 (오류를 코드로 판단하는 처리가 깨짐)
- 상태: 올릴 준비 됨

```text
[제보] 토큰 발급 오류 응답의 errorStatus 가 문자열/숫자로 섞여 오고, 문서에 없는 EGW000·원인과 다른 EAU030 메시지가 있습니다

팀: team-06
환경: 모의 (apidemo.futures.co.kr), 2026-11-20 23:34 최초, 23:35 재현
대상: 접근토큰 발급 POST /auth-service/v1/token, 웹소켓 키 발급 GET /permission/v1/web-socket-key
      오류 코드 페이지 https://apidev.futures.co.kr/#/api/info/error-code

재현 절차:
  1. 토큰 발급을 아래처럼 보내고 오류 응답을 비교
     (a) grant_type 없음 (form)  (b) appkey 없음 (form)  (c) grant_type 을 password 로  (d) appsecret 틀림
     (e) 같은 값을 form 이 아닌 JSON 본문으로
  2. 웹소켓 키 발급을 Authorization: {토큰} (Bearer 없이) 으로

기대 결과:
  오류 응답이 같은 형식이고, 코드는 오류 코드 페이지에 있으며, 메시지가 원인을 알려 줌

실제 결과:
  (a) EAU030 「필수 파라미터 누락: grant_type」  errorStatus: "BAD_REQUEST" (문자열)
  (b) EAU030 「필수 파라미터 누락: appkey」      errorStatus: "BAD_REQUEST" (문자열)
  (c) EAU023 「잘못된 파라미터: grant_type」     errorStatus: 400 (숫자)
  (d) EAU025 「잘못된 appkey 또는 appsecret」    errorStatus: 400 (숫자)
  → 같은 API 의 같은 HTTP 400 인데 errorStatus 타입이 다름 (이번에 확인한 다른 오류 EGW023·EG047·EGW000·ERC002·ESTAT003 은 모두 숫자)
  (e) JSON 본문 → EAU030 「필수 파라미터 누락: appkey」
      → appkey 는 보냈는데 「누락」. 실제 원인은 Content-Type(form 이 아님). 다른 API 는 Content-Type 이 틀리면 HTTP 415 ERC000 「지원하지 않는 Content-Type」(11/20 확인)
  웹소켓 키를 Bearer 없이 → HTTP 401 EGW000 「인증 오류가 발생했습니다. 관리자에게 문의해 주세요.」
      → EGW000 은 오류 코드 페이지에 없고, 메시지로 원인(Bearer 누락)을 알 수 없음. 깨진 토큰은 EG047, 헤더 없음은 EGW023 으로 구분되는 것과 대조됨
  토큰 발급 오류의 errorPath 는 공개 경로 /auth-service/v1/token 이 아니라 내부 경로 /v1/oauth2/token

로그·캡처: (저장소) error_reports/1-인증/logs/auth_20261120_233527.json (T2~T6·W5), 재현 스크립트 error_reports/1-인증/check_auth.py
영향:
  - errorStatus 를 숫자로 비교하는 오류 처리가 EAU030 에서 실패함
  - JSON 으로 보낸 사람은 「appkey 누락」을 보고 키 문제로 오해함 (실제로는 form-urlencoded 로 보내야 함)
  - EGW000 은 문서에 없어 대응 방법을 찾을 수 없음
개선 제안:
  1) errorStatus 를 숫자로 통일, errorPath 는 공개 경로로
  2) 토큰 발급에 form 이 아닌 본문이 오면 ERC000 또는 「form-urlencoded 로 보내야 합니다」 안내
  3) EGW000 을 오류 코드 페이지에 추가하고, Bearer 접두어가 없을 때 그 사실을 알려 주는 메시지로
```
