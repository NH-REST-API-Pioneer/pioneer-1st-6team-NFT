# R08 · 토큰 발급을 POST 가 아닌 메서드로 부르면 GET 은 200 + 빈 응답, PUT 은 404 가 옵니다

- 섹터: 1 · 종류: 서버 동작 (오류를 정상처럼 응답) · 검증: 실제 호출 · AI 영향: 중
- 상태: 올릴 준비 됨

```text
[제보] 접근토큰 발급을 GET 으로 부르면 오류 없이 HTTP 200 + 빈 본문이 옵니다 (다른 API 는 ERC002)

팀: team-06
환경: 모의 (apidemo.futures.co.kr), 2026-11-20 23:34 최초, 23:35 재현
대상: 접근토큰 발급 POST /auth-service/v1/token  https://apidev.futures.co.kr/#/api?g=10&a=8&v=1

재현 절차:
  1. GET /auth-service/v1/token  (본문 없이, 또는 ?grant_type=client_credentials)
  2. 비교: PUT /auth-service/v1/token
  3. 비교: GET /trade/v1/domestic/price (명세 POST), POST /permission/v1/web-socket-key (명세 GET)

기대 결과:
  명세 메서드(POST)가 아니므로 오류 코드로 거절. 오류 코드 페이지의 ERC002 「허용되지 않는 HTTP Method 전송」

실제 결과:
  GET  /auth-service/v1/token          → HTTP 200, Content-Type 없음, 본문 비어 있음 (2회 모두)
  PUT  /auth-service/v1/token          → HTTP 404 {"timestamp":…,"status":404,"error":"Not Found","path":"/v1/oauth2/token"}
  POST /permission/v1/web-socket-key   → HTTP 405 {"timestamp":…,"status":405,"error":"Method Not Allowed","path":"/v1/oauth2/token/web-socket-key"}
  GET  /trade/v1/domestic/price        → HTTP 400 {"errorCode":"ERC002","errorMessage":"오류가 발생 하였습니다.\n관리자에게 문의 하세요.",…}   ← 대조군
  → 같은 「메서드가 틀림」인데 토큰 발급만 200(성공 코드)으로 답하고, 인증 API 는 ERC002 대신 다른 형식(timestamp/status/error/path)으로 답함
  → 404·405 응답의 path 가 공개 경로가 아닌 내부 경로(/v1/oauth2/token…)로 나옴

로그·캡처: (저장소) error_reports/1-인증/logs/auth_20261120_233527.json (T7·X3·X4·W2·X2), 재현 스크립트 error_reports/1-인증/check_auth.py
영향:
  - HTTP 상태 코드로 성공을 판단하는 클라이언트는 토큰 발급이 「성공」했다고 보고 빈 본문에서 access_token 을 찾다가 엉뚱한 곳에서 실패함 (응답이 JSON 도 아니라 파싱 오류)
  - 메서드 오류를 ERC002 로 처리하는 공통 오류 처리가 인증 API 에서는 동작하지 않음
개선 제안:
  1) 인증 API 도 잘못된 메서드에 ERC002(또는 405)를 같은 오류 형식({"errorCode","errorMessage",…})으로 반환
  2) 오류 응답의 path 에 내부 경로 대신 공개 경로를 표시
참고: ERC002 의 메시지가 「오류가 발생 하였습니다. 관리자에게 문의 하세요.」로, 오류 코드 페이지 설명(「허용되지 않는 HTTP Method 전송」)과 달라 원인을 알기 어렵습니다.
```
